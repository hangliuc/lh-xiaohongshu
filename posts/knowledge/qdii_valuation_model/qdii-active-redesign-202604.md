# QDII 主动型基金估值模型 — 全新设计与回测

基金：**012922 易方达全球成长精选**  
回测窗口：**2026-04-01 ~ 2026-04-30**  
季报报告期：**2026-03-31**  
生成时间：2026-05-15 16:12

## 0. 痛点与设计目标

美股 04:00 收盘 → 国内基金 19:00-22:00 更新净值，中间约 15 小时信息真空。
QDII 主动型基金估算的两大死结：

1. **持仓滞后** — 季报披露的是上季度末时点持仓，最长滞后 1 季度。
2. **长尾不透明** — 前 10 仅覆盖 ~50% 净值，剩余约 50% 中既有股票也有现金/其他基金。

## 1. 全新模型设计

完全独立设计，以下 5 个方案，逐步从「简单」走向「精细+自校准」：

### 方案一 — 纯前十大持仓加权法

最朴素的思路：基金披露什么我们就算什么。

```
估算 = Σ_{i=1..10} (持仓i占比 × 持仓i今日涨跌)

占比来自季报；涨跌来自当日行情。
剩余约 48% 仓位（前 10 之外的股票 + 现金 + 债券）默认涨跌 0%。
```
**优点**：简单透明，每个数字用户都能看到来源。  
**缺点**：把约一半的仓位当成「不动」，会系统性低估涨跌幅度。

### 方案二 — 行业 ETF 替身法

完全跳过个股，直接用行业代理 ETF。

```
估算 = Σ_j (行业j占比 × 行业j代理ETF今日涨跌)

信息技术 → XLK，工业 → XLI，电信服务 → XLC
能源 → XLE，材料 → XLB，保健 → XLV
非必需消费品 → XLY，必需消费品 → XLP，金融 → XLF
```
**优点**：覆盖全部已披露的股票仓位（84.75%）。  
**缺点**：丢失了基金经理的选股 alpha；持仓越集中，误差越大。

### 方案三 — 前十持仓 + 行业残余补全法

方案一和方案二的折中：前 10 用真实股票，剩余的按行业用 ETF 补。

```
估算 = Σ_{i=1..10} (持仓i占比 × 持仓i今日涨跌)        ← 已披露
     + Σ_j (行业j占比 - 前10在j的占比) × 行业j代理ETF涨跌  ← 残余

做法：
  1) 把每只前 10 重仓股按 GICS 归到对应行业
  2) 行业总占比里减去前 10 已经占用的部分，剩下的就是「行业残余」
  3) 行业残余用对应行业 ETF 估算
```
**关键创新**：前 10 用「真实涨跌」，避免行业 ETF 抹平选股 alpha；
剩余仓位用「行业 ETF」，避免方案一直接归零。

### 方案四 — 地区 × 行业 网格法

在方案三上多加一个维度：把每个仓位拆到「地区 × 行业」二维网格。

```
网格(地区r, 行业j) 权重 = 地区r占比 × (行业j占比 / 行业总占比)

对每个网格：
  - 前 10 中有股票落在该网格 → 用真实股票涨跌
  - 否则 → 用 (地区, 行业) 对应的代理：
       (美国, 信息技术) → XLK
       (中国内地, 信息技术) → 信息技术 ETF (159939)
       (中国香港, 信息技术) → 恒生科技 ETF (513180)
       (日本, 任何) → EWJ
```
**为什么要分地区**：QDII 的港股、A 股、美股交易时间不同步，
单纯用美股 ETF 估算会忽略当天 A 股、港股的实际涨跌。

**前提假设**：每个地区内的行业分布与基金整体相同（季报不公布交叉表）。

### 方案五 — 方案四 + 历史误差自校准

在方案四（精度最高的基础模型）的估算上，叠加一个「最近几天的偏差均值」。

```
校准后估算 = 方案四估算 + 最近偏差

最近偏差 = 最近 N 天 (实际净值涨跌 - 方案四估算) 的指数加权平均
         = Σ λ^age × (实际_t - 方案四_t) / Σ λ^age

λ = 0.6（衰减系数），N = 10（窗口）
权重示意：今天 1.0，前 1 天 0.6，前 2 天 0.36，前 3 天 0.22 ...
```
**为什么用方案四做底**：方案四 MAE 最低（0.497%），在它上面做校准起点更高。
方案四的残余偏差主要来自「地区×行业交叉分布假设」和「基金调仓」，
EWMA 残差校正正好能把这些系统性偏差消掉。

### 方案六 — 方案四 + 历史误差自校准

和方案五完全相同的校准方法，但底座换成方案四（地区×行业网格）。

```
校准后估算 = 方案四估算 + 最近偏差

最近偏差 = 最近 N 天 (实际净值涨跌 - 方案四估算) 的指数加权平均
```
**为什么要同时保留方案五和方案六**：
- 方案五（方案三+校准）：实现简单，只需美股 ETF 数据，适合 API 调用受限的场景
- 方案六（方案四+校准）：精度更高，但需要 A 股/港股/日股 ETF 数据，依赖更多数据源
- 两者对比可以量化「加入地区维度」到底值多少精度

### 补充讨论：Q1 季报 + 年报全持仓组合方案

这个方案的思路是：

```
前 10 大持仓 → 用最新季报（占比最精确，2026-03-31）
第 11 及之后 → 用年报公开的全持仓（2025 年报，覆盖率高但数据旧半年）
合并去重后，按实际覆盖率还原：

估算 = [Σ(合并持仓涨跌 × 占比)] / 实际覆盖率
```

**优点**：
- 覆盖率极高（年报通常披露 30-80 只股票，覆盖 70-90% 仓位）
- 不需要代理 ETF，全部用真实个股涨跌

**缺点**：
- 年报数据滞后半年（2025 年报反映的是 2025-12-31 的持仓），基金经理半年内可能大幅调仓
- 第 11 及之后的股票占比用的是年报数据，与当前实际偏差可能很大
- 需要拉取 30-80 只股票的实时行情，API 调用量大、延迟高

**本次未纳入回测的原因**：
- 012922 的 2025 年报全持仓数据在天天基金接口中返回不完整（仅返回前 10）
- 即使数据完整，半年前的持仓对 2026 年 4 月的估算参考价值有限
- 方案四（地区×行业网格）+ 方案五（自校准）已经达到 MAE 0.47%，
  年报方案即使数据完美也很难超越（因为半年前的持仓权重已经过时）

**建议**：如果未来天天基金接口能稳定返回年报全持仓，可以作为方案三的替代——
用真实个股替代行业 ETF 来填补「前 10 之外」的仓位。
但需要注意：年报占比 ≠ 当前占比，仍然需要叠加自校准（方案五）来修正偏差。

## 4. 误差汇总

### 名词解释

| 指标 | 全称 | 含义（白话） |
|------|------|------------|
| **MAE** | Mean Absolute Error（平均绝对误差） | 把每天的「估算 - 实际」取绝对值再求平均。**越小越好**，代表"平均每天偏了多少"。 |
| **Bias** | 偏差（平均误差，带正负号） | 把每天的「估算 - 实际」直接求平均（不取绝对值）。正数 = 系统性高估，负数 = 系统性低估，0 = 无偏。 |
| **最大误差** | Max Absolute Error | 所有交易日中，偏差绝对值最大的那一天。衡量"最坏情况有多离谱"。 |
| **<0.3% 命中** | — | 误差绝对值 < 0.3% 的天数占比。越高说明"大部分时候估得很准"。 |
| **<0.5% 命中** | — | 误差绝对值 < 0.5% 的天数占比。0.5% 是用户体感上"可接受"的阈值。 |

**举例**：方案三 MAE = 0.549% 意味着平均每天估算偏差约 0.55 个百分点；
Bias = -0.295% 说明它倾向于低估（估出来的涨跌比实际小 0.3 个百分点左右）。

## 6. 历史校准能否让小程序估算越来越准？

能，但要做对。三个层次依次升级：

### 6.1 一阶偏差校正（已实现 = 方案五）

用最近若干天的「实际 - 方案四估算」做指数加权平均，作为 bias 加在估算上。
这一项就能修复：
- 季报披露的总仓位误差（默认假设 90% 仓位 vs 实际 84.75%）；
- 行业分类错配（基金披露的 GICS 分类与代理 ETF 行业不完全对应）；
- 系统性低估或高估（看 §4 表 bias 列就能看出来）。

### 6.2 二阶系数校正（建议进阶）

**一句话**：方案六只修了「上下平移」，二阶还修了「放大/缩小」。

方案六的公式是：`校准后 = 方案四估算 + bias`，相当于在估算上加一个常数。
但如果基金经理最近加了杠杆或集中度变高，实际涨跌幅度会比方案四估算「放大」——
这时候光加一个常数不够，还需要乘一个系数。

**做法**：取最近 N 天（比如 20 天）的数据，画一条直线拟合：

```
实际涨跌 = a × 方案四估算 + b
```

其中：
- **a（斜率）**= 放大系数。a > 1 说明实际波动比方案四估算大（基金比我们想的更激进），
  a < 1 说明实际波动比估算小（基金比我们想的更保守）。
- **b（截距）**= 固定偏移。和方案六的 bias 类似，修正系统性高估/低估。

**为什么比方案六更进一步**：
- 方案六只有 b（加一个常数），相当于 a=1 固定不动；
- 二阶同时学 a 和 b，能适应「基金实际波动幅度 ≠ 估算幅度」的情况。

**举例**（基于方案六的回测数据）：

假设用 4 月份前 20 天的方案四估算 vs 实际净值做线性回归，拟合出 a=1.18, b=-0.05%。
这意味着：基金实际波动是方案四估算的 1.18 倍（因为前 10 之外的股票波动率高于代理 ETF）。

今天方案四估算 = +2.0%，则：
```
二阶校准后 = 1.18 × 2.0% + (-0.05%) = +2.31%
```
对比方案六：`2.0% + bias(假设 -0.28%) = +1.72%`，二阶校准更接近实际。

**什么时候 a ≠ 1**：
- 基金经理季度内大幅加仓（实际仓位 > 季报披露的 84.75%）→ a > 1
- 基金经理减仓或持有大量现金 → a < 1
- 前 10 之外的股票波动率远高于代理 ETF → a > 1

**注意**：二阶校正需要至少 20 天数据才能拟合出稳定的 a 和 b，
数据不足时容易过拟合（a 值不稳定），所以设定 20 天为开启门槛。

### 6.3 多模型集成（探索方向，暂无回测数据支撑）

**⚠️ 注意：以下方案是理论上的进阶方向，本次回测未实现，没有实际 MAE 数据支撑。**
**是否值得实现需要后续单独回测验证。**

**思路**：每天我们有 4 个基础估算（方案一/二/三/四），把它们加权混合：

```
最终估算 = p₁×方案一 + p₂×方案二 + p₃×方案三 + p₄×方案四 + b

约束：p₁ + p₂ + p₃ + p₄ = 1，且每个 p ≥ 0
```

**p₁~p₄ 怎么来的**：用最近 30 天的「实际净值涨跌」和「4 个方案的估算」，
做一个带约束的最小二乘拟合，找出让过去 30 天误差最小的权重组合。

**理论上为什么可能有用**：
- 如果基金最近调仓很少，方案一（纯前十）就够准 → p₁ 会变大
- 如果基金最近大幅调仓，前十已经不代表真实持仓 → p₂（行业 ETF）权重会上升
- 如果 A 股/港股仓位波动大 → p₄（地区×行业网格）权重会上升

**风险**：
- 30 天数据拟合 5 个参数（p₁~p₄ + b），自由度低，容易过拟合
- 方案一~四之间高度相关（共线性），权重可能不稳定
- 实际效果可能不如简单的「方案六（方案四+bias）」
- **建议**：先把方案六跑稳，后续有余力再单独回测验证集成方案是否真的更优

### 6.4 实施建议（小程序落地）

基于回测结论，推荐的最严谨落地路径如下：

#### 推荐方案选择

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 数据源完整（美股+A股+港股 ETF 都能拉到） | **方案六**（方案四+自校准） | MAE 最低 0.468%，<0.5% 命中 67% |
| 数据源受限（只能拉美股） | **方案五**（方案三+自校准） | 不依赖 A 股/港股 ETF，MAE 0.551% |
| 冷启动（无历史数据） | **方案四**（地区×行业网格） | 无需历史校准，MAE 0.497% |

#### 分阶段演进

| 阶段 | 触发条件 | 计算逻辑 | 向用户展示 | 预期 MAE |
|------|---------|---------|----------|---------|
| ① 冷启动 | 新基金 / 新季报刚发布 | 方案四（地区×行业网格） | 方案四估算值 | ~0.50% |
| ② 一阶校准 | 累积 ≥ 5 天实际净值 | 方案六 = 方案四 + EWMA bias | 方案四 + bias | ~0.47% |
| ③ 二阶校准 | 累积 ≥ 20 天 | a × 方案四 + b（线性回归） | 校准后估算 | 待回测验证 |
| ④ 多模型集成（可选） | 累积 ≥ 30 天 | p₁·方案一 + ... + p₄·方案四 + b | 集成估算 | 待回测验证 |
| ⑤ 季报更新 | 新季报发布 | 更新持仓/行业/地区，清空历史缓存 | 回到阶段 ① | — |

#### 为什么冷启动用方案四而不是方案三

- 方案四 MAE 0.497% < 方案三 0.549%，即使没有历史校准也更准
- 方案四多用了地区分布数据（美国 46% / 中国内地 33% / 香港 4.5% / 日本 1.2%），
  能区分「A 股信息技术 ETF +6.56%」和「美股 XLK +3.10%」的差异
- 代价是多拉 3 个 ETF 数据（159939、513180、EWJ），API 调用量增加约 3 次

#### 降级策略（容错）

| 异常情况 | 降级方案 |
|---------|---------|
| A 股/港股 ETF 数据拉取失败 | 降级到方案五（方案三+校准），只用美股 ETF |
| 美股 ETF 数据也拉取失败 | 降级到方案一（纯前十持仓），只用个股行情 |
| 个股行情部分缺失 | 缺失的股票贡献按 0 计算，标注「部分数据缺失」 |
| 历史净值回填失败（actual 缺失） | 暂停校准，继续用上一次的 bias/系数 |

#### 定时任务设计

```
┌─────────────────────────────────────────────────────────────┐
│ 每日凌晨 04:30（美股收盘后）                                  │
│   1. 拉取前 10 持仓股票的最新收盘价                            │
│   2. 拉取代理 ETF（XLK/XLI/XLC/... + 159939/513180/EWJ）      │
│   3. 计算方案一~四的当日估算                                   │
│   4. 读取历史缓存，计算方案五/六（叠加 bias）                    │
│   5. 写入当日估算到数据库，推送给用户                            │
├─────────────────────────────────────────────────────────────┤
│ 每日晚 22:00（基金净值更新后）                                 │
│   1. 拉取基金当日实际净值涨跌                                  │
│   2. 回填 actual 字段到历史缓存                                │
│   3. 重新计算 bias / 回归系数 / 集成权重（为明天准备）            │
└─────────────────────────────────────────────────────────────┘
```

#### 数据存储结构

每基金一个文档（云数据库 / 云存储 JSON）：

```json

  "report_date": "2026-03-31",
  "holdings": [...],
  "industries": [...],
  "regions": [...],

  },
  "history": [
    {"date": "2026-04-01", "actual": 2.68, "s1": 1.53, "s2": 1.14, "s3": 1.93, "s4": 2.19},

  ]
```

#### 季报更新流程

1. 检测到新季报发布（每年 1/20、4/20、7/20、10/20 前后）
2. 拉取新的前 10 持仓、行业分布、地区分布
3. 更新 `holdings` / `industries` / `regions` 字段
4. **清空** `history` 数组和 `calibration` 对象
5. 从阶段 ① 重新开始累积
6. 为什么要清空：新季报意味着持仓可能大幅变化，旧的 bias/系数已经不适用
